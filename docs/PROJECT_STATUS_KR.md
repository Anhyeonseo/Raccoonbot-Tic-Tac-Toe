# 프로젝트 현재 상태

기준일: 2026-08-29  
단계: **부스 운영용 MVP 완료 · 실제 장비 최종 검증 완료**

## 완료 결과

고정 RGB 카메라가 3×3 보드의 빨강·노랑 말을 읽고, 참가자의 수를 검증한 뒤,
불완전 AI가 선택한 수를 RaccoonBot이 실제로 수행한다. 로봇 동작 후 카메라가
예상 상태와 실제 상태가 일치하는지 재확인한 경우에만 게임 상태를 확정한다.

소형 보드와 전용 카메라 거치대 기준으로 stock→cell 배치, cell→cell 이동,
집기·놓기, 높은 운반 경로와 게임 완주를 실제 장비에서 검증했다. 브라우저 UI에서
게임 시작, 사람 턴 제출, 진행 상태, 보드 표시, 오류 재시도, 협력식 중단, 화면
초기화와 현장 재캘리브레이션을 수행할 수 있다.

데스크톱 자동 테스트 **109개**, Python 컴파일, JavaScript와 셸 스크립트 문법
검사를 통과했다.

## 확정 구성

| 항목 | 구성 |
|---|---|
| 컴퓨팅 | Jetson Orin Nano DevKit, 512GB NVMe |
| OS | Ubuntu 24.04.3 LTS |
| JetPack / L4T | JetPack 7.2.1 / L4T R39.2.1 |
| CUDA / OpenCV | CUDA 13.2 / OpenCV 4.8.0 |
| 카메라 | Trust QHD Webcam, MJPEG 1920×1080 30fps |
| 로봇 연결 | Mini Dongle+ USB 직렬 + RaccoonBot BLE |
| 말 / 보드 | 사람 빨강 3개, 로봇 노랑 3개 / 고정형 흑백 3×3 보드 |
| 로봇 프로필 | 27자세, 직접 관절 이동, 최고 속도 60, 도달 오차 3° |

카메라는 현재 설치에서 노출 333, 화이트밸런스 4600K, gain 64를 기준으로
고정했다. 이 값은 장비 위치와 조명에 종속되므로 현장에서 영상과 색 비율을 다시
확인한다.

## 게임과 AI

- 참가자 선공, 각 3말 배치 후 원하는 빈칸으로 자유 이동하는 3목 규칙
- 배치 중 승리, 이동 중 승리, 3회 상태 반복, 이동 단계 10턴 제한 처리
- `쉬움`: 즉시 승리는 항상 선택, 방어 40%, 최선 수 35%, 차선 수 25%
- `보통`: 즉시 승리는 항상 선택, 방어 70%, 최선 수 60%, 차선 수 25%
- 고정 난수 시드는 시험용으로 지원하고 현장 기본은 매 게임 시스템 난수 사용
- 사람 행동이 잘못되면 로봇을 움직이지 않고 보드 수정과 재확인을 요청

쉬움 AI는 초등학생이 이길 기회를 늘리기 위한 현장 기본값이다. 초반에도 항상
져 주도록 결과를 조작하지는 않으므로 플레이에 따라 라쿤봇이 이길 수 있다.

## 카메라와 보드 인식

- 네 모서리 원근 보정과 고정된 1~9번 셀 분할
- HSV 기반 빨강·노랑·빈칸 분류
- 5프레임 중 4프레임이 일치해야 상태를 확정하는 안정화
- 사람 입력 전후 보드 차이에서 배치 또는 이동 행동 추론
- 고정 카메라에서 보드와 말 연속 인식 검증
- 브라우저에서 촬영 → 6점 선택 → 왜곡 보정 미리보기 → 명시적 저장
- 저장 전 기존 `vision.json`의 타임스탬프 백업 생성

## RaccoonBot

- 공식 `robomation.RaccoonBot` Python API 사용
- 배터리, BLE, DC 그리퍼 종류와 상태 사전 검사
- `home`, `home_high`, `transit`, 9개 셀과 3개 stock의 hover/grasp: 총 27자세
- 모든 자세의 누락·임시값·관절 범위 정적 검증
- 공식 `set_angle_joints(..., wait=True)` 직접 이동을 기본 사용
- 이동 후 최대 관절 오차 3° 검사, 실패 시 같은 자세 최대 2회 재전송
- 왕복 경로: `home → home_high → transit → 작업 → transit → home_high → home`
- 집은 말을 `transit`까지 올린 뒤 이동해 다른 말을 치는 문제 방지
- 보간 이동은 문제 진단용 옵션으로만 유지
- 카메라 없이 말 하나를 `1→2→3→4→5→6→7→8→9`로 연속 운반한 뒤
  `home` 복귀까지 실제 장비에서 최종 확인

새 RaccoonBot 연결 직후 J1이 초기 방향으로 움직일 수 있어 게임 시작 시
`transit → home_high → home` 관찰 진입을 거친 뒤 카메라를 사용한다.

## 브라우저 운영과 복구

- Jetson에서 게임·카메라·로봇을 실행하고 노트북은 SSH 터널로 접속
- 현장 기본 USB-C 장치망 `hyper@192.168.55.1`
- 개발실 Wi-Fi `hyper@192.168.35.236`도 같은 실행 스크립트로 선택 가능
- `내 차례 완료` 버튼과 키보드 `Enter` 입력
- 인식 실패 시 `다시 확인`
- 현재 관절 이동이 끝난 다음 명령 경계에서 멈추는 `게임 중단`
- 로봇을 움직이지 않고 화면 상태를 비우는 `화면 초기화`
- 게임 중에는 캘리브레이션 API와 촬영 버튼 차단

굿즈 버튼은 사용하지 않는다. `게임 중단`은 물리 비상정지가 아니므로 즉시 정지가
필요한 상황의 전원 차단과 사람 접근 통제는 현장 절차로 별도 운영한다.

## 배포 시 확인

개발 구현과 현재 장비 검증은 완료했다. 설치 장소가 바뀌면 다음 항목은 현장에서
다시 확인한다.

1. 행사 노트북과 USB-C 케이블로 `192.168.55.1` 접속
2. 카메라·보드·로봇 고정 상태와 캘리브레이션 미리보기
3. 필요 시 `vision.json` 재저장 및 자세 재teaching
4. 쉬움 AI 빈 판 한 게임 완주
5. 잘못 둔 수의 수정·재확인 흐름
6. 사람 턴 대기 중 게임 중단 → 화면 초기화 → 새 게임

장시간 반복 내구 시험과 USB HID 굿즈 버튼은 사용자 결정에 따라 완료 조건에서
제외했다.

## 실행

```bash
RACCOONBOT_SSH_IDENTITY=/path/to/private-key bash scripts/run_booth_ui.sh
```

개발실 Wi-Fi 사용:

```bash
RACCOONBOT_JETSON_TARGET=hyper@192.168.35.236 \
RACCOONBOT_SSH_IDENTITY=/path/to/private-key \
bash scripts/run_booth_ui.sh
```

브라우저 주소는 두 경우 모두 `http://127.0.0.1:8080`이다. 상세 운영과 복구,
재캘리브레이션 순서는 `BOOTH_UI_KR.md`를 따른다.

## 저장소 공개 전 확인

- `config/vision.json`, `config/robot_poses.json`, `work/`는 장비별 데이터이므로

- `python3 -m pytest -q`와 `raccoonbot-validate-poses config/robot_poses.json`을
  실행한다.
- Git 커밋과 push는 프로젝트 소유자가 직접 수행한다.
