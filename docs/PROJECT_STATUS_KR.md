# 프로젝트 현재 상태

기준일: 2026-08-26  
단계: **1차 MVP 완료**

## MVP 결과

고정 카메라가 3×3 보드의 빨강·노랑 말을 읽고, 참가자의 수를 검증한 뒤,
불완전한 AI가 선택한 수를 RaccoonBot이 실제로 수행하는 전체 흐름을 완성했다.
로봇 동작 후에는 카메라가 예상 보드와 실제 보드가 일치하는지 다시 확인한
경우에만 내부 게임 상태를 확정한다.

실제 장비에서 빈 판으로 시작한 게임 2판을 끝까지 진행했다. 두 게임 모두
사람 수 인식, 노란 말 3개 배치, 로봇 결과 재검증, 이동 단계 진입과 사람 승리
판정까지 정상 동작했다. 두 번째 게임은 시연 영상으로 촬영했다.

## 구현 완료 범위

### 게임과 AI

- 참가자 선공, 각 3말 배치 후 자유 이동하는 3목 규칙
- 8개 승리선, 3회 상태 반복과 이동 10턴 제한
- 즉시 승리는 항상 선택하고 나머지 수에는 확률적 실수를 허용하는 AI
- 고정 난수 시드를 지원하는 대화형·자동 경기 시뮬레이터
- 배치와 이동 단계에서 참가자 행동의 합법성 검증

### 카메라와 보드 인식

- 네 모서리 원근 보정과 고정된 1~9번 셀 분할
- HSV 기반 빨강·노랑·빈칸 분류
- 5프레임 중 4프레임이 일치해야 상태를 확정하는 안정화
- 참가자 입력 전후 보드 차이에서 배치 또는 이동 행동 추론
- 현장용 캘리브레이션, 정지 사진 검사, 연속 관찰 CLI
- 고정 카메라 설정에서 빨강 3개와 노랑 3개 동시 인식 검증
- 말이 칸 중앙에서 벗어났던 장면까지 포함한 저장 영상 6개 교차검증

최종 보정에서는 실제 판의 아래 테두리에 맞게 보드 영역을 조정해 판 밖의
대기 말이 9번 칸에 포함되지 않도록 했다. 실제 장비별 `vision.json`은 설치
위치와 조명에 종속되므로 저장소에 포함하지 않는다.

### RaccoonBot

- 공식 `robomation.RaccoonBot` Python API 어댑터
- 배터리, BLE 연결, DC 그리퍼 종류와 상태 사전 검사
- `home`, `transit`, 9개 셀과 3개 stock의 hover/grasp teaching
- 필수 자세 26개 검증 완료, 누락·임시 자세 없음
- 9개 셀과 stock 3곳의 실제 말 제자리 픽앤플레이스 성공
- `stock 1 → cell 5` 실제 배치와 `cell 5 → cell 9` 자유 이동 성공
- 모든 관절을 동시에 보간하는 위치 이동
- 말을 집은 뒤 높은 `transit`을 경유해 다른 말을 치지 않는 운반 경로
- 실제 게임용 속도 45, 관절당 최대 보간 간격 6° 검증
- 속도 45의 `transit ↔ home` 왕복 도달 오차 최대 0.352° 확인

### 전체 통합

- `Enter`를 사람 턴 완료 신호로 사용하는 실제 장비 게임 러너
- 빈 보드 시작 검사와 중단된 배치판 재개 옵션
- 사람 수 인식 → AI 판단 → 실제 집기·놓기 → 카메라 재검증
- 로봇 결과 불일치 시 상태 갱신을 보류하고 운영자 재촬영 대기
- 실제 게임 캡처 이미지를 `work/game-captures`에 저장
- 데스크톱과 Jetson에서 자동 테스트 **87개 통과**

## 검증 장비

| 항목 | 확인된 구성 |
|---|---|
| 컴퓨팅 | Jetson Orin Nano DevKit, 512GB NVMe |
| OS | Ubuntu 24.04.3 LTS |
| JetPack / L4T | JetPack 7.2.1 / L4T R39.2.1 |
| CUDA / OpenCV | CUDA 13.2 / OpenCV 4.8.0 |
| 카메라 | Trust QHD Webcam, MJPEG 1920×1080 30fps |
| 로봇 연결 | Mini Dongle+ USB 직렬 + RaccoonBot BLE |
| 말 | 참가자 빨강 3개, 로봇 노랑 3개 |
| 보드 | 고정형 3×3 흑백 체스판 |

카메라는 노출 333, 화이트밸런스 4600K, gain 64를 기준으로 고정했다. 장비를
옮기거나 현장 조명이 달라지면 같은 숫자를 그대로 복사하지 말고 다시 촬영해
보드 모서리와 색 범위를 검증한다.

## 실제 운영 순서

1. 로봇, 보드, stock과 카메라가 움직이지 않도록 고정한다.
2. 노란 말 3개를 stock 1~3에 놓고 빨간 말은 참가자 쪽에 둔다.
3. 판을 완전히 비우고 사람과 로봇의 손이 작업 영역 밖에 있는지 확인한다.
4. 카메라 고정값을 적용한다.
5. 실제 게임 러너를 실행한다.
6. `사람 차례입니다`가 출력된 뒤에만 빨간 말을 놓거나 옮긴다.
7. 손을 완전히 뺀 뒤 `Enter`를 누른다.
8. 로봇 동작과 카메라 검증이 끝날 때까지 작업 영역에 손을 넣지 않는다.

```bash
bash scripts/configure_camera.sh /dev/video0
raccoonbot-play-hardware --joint-step 6 --seed 0 --confirm-hardware
```

중단된 배치 단계의 물리 보드를 이어갈 때만 아래 옵션을 사용한다.

```bash
raccoonbot-play-hardware --joint-step 6 --seed 0 \
  --resume-placement --confirm-hardware
```

## 현재 알려진 한계

- 실제 게임은 전체 화면 UI가 아닌 터미널 프롬프트로 운영한다.
- 사람 턴 완료 입력은 키보드 `Enter`이며 USB HID 굿즈 버튼은 아직 연결하지 않았다.
- 안전 중심의 높은 운반 경로와 보간 이동 때문에 로봇 한 수에 약 1분 30초~2분이
  걸릴 수 있다.
- 실제 완주 게임에서는 사람이 이동 단계 첫 수에 승리해 로봇의 셀 간 이동이
  나오지 않았다. 셀 간 이동 자체는 별도 실물 운반 시험으로 검증했다.
- BLE가 관찰 자세 왕복 중 일시적으로 재연결된 사례가 있어 장시간 반복 운전
  전 별도 내구 시험이 필요하다.
- 운영자용 물리 비상정지와 행사장 안전 가드는 소프트웨어 턴 완료 버튼과 별도로
  준비해야 한다.

## MVP 이후 우선순위

1. 전체 화면 부스 UI와 실제 장비 게임 러너 통합
2. USB HID 굿즈 버튼을 `Enter` 입력으로 연결
3. 운영자 비상정지·초기화·재연결 절차 리허설
4. 30~50게임 연속 운전과 다양한 셀 간 이동 시험
5. 안전성을 유지하면서 중복 경로와 보간 구간을 줄이는 속도 최적화
6. 행사장 조명에서 카메라 재캘리브레이션 및 3회 테스트 게임
