# 기술 설계와 검증 상태

## 1. 목표와 범위

이 프로젝트는 초등학생·중학생 체험 부스에서 사용할 3개 말 이동형 3목 게임입니다.
Jetson 한 대가 카메라 관찰, 규칙 검증, AI 수 선택과 RaccoonBot 동작을 담당하며,
노트북은 SSH 터널을 통한 운영 화면만 표시합니다. ROS, 클라우드 추론과 학습 모델은
사용하지 않습니다.

## 2. 게임 모델

- 사람은 빨강, 로봇은 노랑이며 사람 선공입니다.
- 각자 3개를 번갈아 배치한 뒤 이동 단계로 전환합니다.
- 이동 단계에서는 자기 말 하나를 임의의 빈칸으로 옮깁니다.
- 가로·세로·대각선 3목이 생기면 즉시 종료합니다.
- 같은 보드와 차례가 3회 반복되거나 이동 단계가 10수를 넘으면 무승부입니다.

`easy` AI는 방어 40%, 최선 수 35%, 두 번째 수 25% 확률을 사용합니다. `normal`은
기본 정책인 방어 70%, 최선 수 60%, 두 번째 수 25%를 사용합니다. 나머지 확률은
무작위 합법 수를 선택하므로 완벽하게 플레이하지 않습니다.

## 3. 실행 구조

```text
RGB Camera
    ↓
원근 보정 → 9칸 색상 판정 → 안정화된 보드 상태
    ↓
사람 행동 검증 → 게임 상태기 → 불완전 AI
    ↓
RaccoonBot 운반 계획 → 동작 → 카메라 결과 재검증

노트북 브라우저 ← SSH 터널 → Jetson 웹 서버
```

| 영역 | 주요 코드 | 책임 |
|---|---|---|
| 규칙·AI | `game.py`, `strategy.py` | 합법 수, 승패·반복 판정, 수 선택 |
| 비전 | `vision/` | 워프, HSV 마스크, 안정화와 행동 추론 |
| 로봇 | `robot/` | 자세 프로파일, 경로 계획, 공식 API 어댑터 |
| 세션 | `app/` | 턴 진행, 검증, 웹 상태와 캘리브레이션 |
| 운영 | `tools/`, `web/` | CLI, 하드웨어 서버와 브라우저 UI |

## 4. 비전 설계

`config/vision.json`의 네 모서리를 이용해 보드를 정사각형으로 원근 변환하고 3×3으로
분할합니다. 각 셀의 가장자리 15%를 제외한 영역에서 HSV 마스크 비율을 계산하며,
빨강 또는 노랑 픽셀이 4% 이상이면 해당 말로 판정합니다.

현재 검증 색상 설정은 다음 특성을 사용합니다.

- 빨강: hue 135~179와 0~15의 순환 범위
- 노랑: hue 20~65
- 낮은 채도·명도 픽셀 제외
- 연속 프레임이 일치할 때만 턴 상태로 채택

현장 웹 캘리브레이션은 보드 네 모서리만 바꾸고 기존 색상 설정을 보존합니다.
촬영 버튼은 로봇을 `transit → home_high → home`으로 옮긴 뒤 연결을 유지한 상태에서
프레임을 얻습니다. 연결 해제로 팔이 기본 자세로 돌아가 보드를 가린 사진이 저장되는
문제를 방지하기 위한 동작입니다.

보드 전체를 덮는 올바른 원근 영역이 중요합니다. 색상 임계값을 낮추는 것만으로는
잘린 셀을 복구할 수 없으므로, 워프 미리보기에서 바깥 테두리와 9칸 전체를 먼저
확인해야 합니다.

## 5. 로봇 동작 설계

장비별 프로파일에는 다음 27개 자세가 있습니다.

- `home`, `home_high`, `transit`
- `cell_1`~`cell_9`의 `hover`, `grasp`
- `stock_1`~`stock_3`의 `hover`, `grasp`

한 번의 운반 경로:

```text
home → home_high → transit
→ source_hover → source_grasp → source_hover
→ transit
→ target_hover → target_grasp → target_hover
→ transit → home_high → home
```

운영 기본값은 공식 `set_angle_joints(..., wait=True)`를 이용한 `direct` 이동입니다.
각 목표 뒤 엔코더 오차를 검사하며 최대 관절 오차가 3°를 넘으면 같은 자세를 최대
2회 재전송합니다. 총 3회 실패하면 다음 그리퍼 동작 전에 게임을 중단합니다.
`interpolated` 모드는 진단용으로 유지합니다.

현재 공식 패키지·펌웨어 조합은 새 연결을 열 때 J1이 0° 쪽으로 이동할 수 있습니다.
따라서 연결 직후 카메라를 읽지 않고 안전 진입 경로를 먼저 실행합니다.

## 6. 설정과 생성 데이터

공개 저장소에는 템플릿만 포함합니다. 다음 파일과 디렉터리는 설치별 데이터이므로
Git에 올리지 않습니다.

- `config/robot_poses.json`
- `config/vision.json`, `config/*.local.json`
- `work/`의 카메라 캡처와 실행 로그

현장 캘리브레이션 저장은 기존 `vision.json`을 타임스탬프 백업으로 보존한 뒤
임시 파일을 원자적으로 교체합니다. 자세 파일에 `_provisional_poses`가 남아 있으면
검증과 실제 로드를 실패시켜 미확인 자세 사용을 막습니다.

## 7. 검증

자동 테스트는 규칙·AI, 비전, 행동 추론, 경로 계획, 웹 상태, 캘리브레이션 저장과
복구를 포함하며 현재 **111개**가 통과합니다.

```bash
python -m pytest -q
python -m compileall -q src tests
node --check src/raccoonbot_game/web/app.js
bash -n scripts/*.sh
```

실제 장비에서는 다음을 완료했습니다.

- 빨강·노랑 말 6개가 놓인 보드의 9칸 판독
- 사람 턴 인식과 로봇 동작 후 결과 재검증
- 배치·이동 단계를 포함한 전체 게임 완주
- 9개 셀과 3개 stock의 hover/grasp 동작
- 말 하나를 `1→2→…→9`로 옮기는 무카메라 연속 운반
- `direct` 이동, 높은 `transit`, `home_high` 경로와 자세 재전송
- 노트북 SSH 터널 UI와 현장 복구·캘리브레이션 화면

자세와 비전 값은 현재 소형 보드와 전용 카메라 거치대에서 검증한 장비별 값입니다.
기구 배치나 말 규격이 바뀌면 운영 문서의 재검증 절차를 다시 수행해야 합니다.
