# RaccoonBot Vision Three-in-a-Row 개발 계획서

## 1. 프로젝트 개요

- 장비: Jetson Orin Nano, RGB 카메라, RaccoonBot, Mini Dongle+
- 대상: 초등학생 및 중학생 체험 부스
- 목표: 카메라가 사람의 수를 인식하고, 불완전한 AI가 판단하며, 로봇팔이 실제 말을 움직이는 3목 게임
- 우선순위: 빠른 구현, 반복 정밀도, 현장 복구 용이성, 안전

기존 조이스틱 부스가 사람이 로봇을 직접 조작하는 체험이라면, 이 시스템은 로봇이 사람의 행동을 보고 판단해 대응하는 체험을 제공한다.

### 현재 진행 상태 (2026-08-29)

부스 운영용 MVP와 실제 장비 시연을 완료했다. 소형 보드 기준 27개 자세,
직접 관절 이동, 실제 게임 완주, 브라우저 운영·복구 UI와 현장 재캘리브레이션을
통합했다. 재teaching한 셀 grasp를 포함해 말 하나의 `1→9` 연속 운반과 홈 복귀를
최종 확인했으며 자동 테스트 109개가 통과한다.

개발 범위는 완료했다. 행사장 설치 시 USB-C 연결, 카메라 캘리브레이션과 한 게임
리허설을 반복한다. 별도 입력 굿즈와 장시간 내구 시험은 이번 완료 조건에서
제외한다. 최신 실기 결과와 실행 절차는 `PROJECT_STATUS_KR.md`를 우선 참고한다.

## 2. MVP 범위

### 포함

- 고정된 3×3 흑백 체스판
- 빨간 말 3개와 노란 말 3개
- 배치 후 자기 말을 원하는 빈칸으로 이동하는 변형 3목 규칙
- 고정 카메라와 보드 캘리브레이션
- HSV 기반 빨강·노랑 인식
- 9개 셀과 말 거치대의 로봇 티칭 포인트
- 의도적으로 완벽하지 않은 AI
- 참가자 행동 유효성 검사
- 로봇 동작 후 카메라 재검증
- 현장용 캘리브레이션 및 진단 도구
- 로컬 오프라인 실행

### 제외

- YOLO 등 학습 기반 검출
- 자유롭게 움직이는 보드
- 임의 위치 물체 집기
- 실시간 hand-eye calibration
- ROS, 클라우드, 음성 및 얼굴 인식
- 모바일 앱

## 3. 확정 게임 규칙

### 기본

- 참가자가 선공한다.
- 참가자는 빨강, 로봇은 노랑을 기본값으로 사용한다.
- 각 플레이어는 말 3개를 사용한다.
- 가로, 세로 또는 대각선으로 3개를 연결하면 승리한다.

### 배치 단계

1. 참가자와 로봇이 빈칸에 말 하나씩 번갈아 배치한다.
2. 매 수 직후 승리 여부를 확인한다.
3. 말 6개가 모두 배치됐는데 승부가 없으면 이동 단계로 넘어간다.

### 이동 단계

1. 자기 말 하나를 선택한다.
2. 현재 위치와 다른 빈칸 어디로든 옮길 수 있다.
3. 인접 칸 제한은 없다.
4. 상대방 말은 움직일 수 없다.
5. 한 턴에 말 하나만 움직인다.

### 종료 제한

- 동일한 보드 상태와 동일한 차례가 3회 등장하면 반복 종료한다.
- 이동 단계는 총 10수로 제한한다. 한 플레이어의 이동 한 번을 1수로 센다.
- 제한 내 승부가 없으면 내부 결과는 무승부, 참가자 화면은 `라쿤봇 방어 성공`으로 표시할 수 있다.

### AI 정책

- 이번 수로 이길 수 있으면 항상 승리한다.
- 현장 기본 `쉬움`: 방어 40%, 최상위 수 35%, 차선 수 25%, 나머지 무작위 수.
- 동작 확인용 `보통`: 방어 70%, 최상위 수 60%, 차선 수 25%, 나머지 무작위 수.
- 고정 난수 시드는 재현 시험에만 사용하고 현장에서는 시스템 난수를 사용한다.

## 4. 물리 설계

### 보드

- 3×3 흑백 체스판을 사용한다.
- 초기 권장 크기는 150×150mm, 셀은 50×50mm다.
- 말보다 셀을 충분히 크게 만들어 외곽선과 격자 교차점이 가려지지 않게 한다.
- 외곽 사각형을 검출하기 쉬운 테두리를 둔다.
- 실제 크기는 로봇이 9칸과 거치대에 모두 도달하는지 확인한 뒤 확정한다.

### 말

- 무광, 고채도 빨강과 노랑을 사용한다.
- 방향을 맞출 필요가 없는 원통형을 권장한다.
- 초기 권장 크기는 지름 30~35mm, 높이 25~35mm다.
- 로봇 집게가 미끄러지지 않는 재질을 사용한다.
- 색상별 3개를 사용하고 최소 1개씩 예비로 준비한다.

### 고정 구조

가능하면 다음 장치를 하나의 베이스판에 고정한다.

- RaccoonBot
- 3×3 보드
- 노란 말 3개 거치대
- 카메라 지지대
- 필요 시 조명 지지대

거치대에는 얕은 홈이나 가이드 링을 두어 말 중심이 반복해서 동일한 위치에 놓이게 한다.

### 카메라와 조명

- 카메라는 보드 전체와 거치대를 볼 수 있게 고정한다.
- 보드 중앙을 수직에 가깝게 내려다보게 한다.
- 캘리브레이션 후 초점, 노출, 화이트밸런스와 게인을 가능하면 고정한다.
- 강한 반사와 참가자 그림자를 줄이는 확산 조명을 사용한다.

## 5. 좌표 및 로봇 제어 전략

카메라는 실제 로봇 좌표를 계산하지 않고 말이 있는 셀 번호만 판정한다. 게임 엔진은 출발 셀과 도착 셀을 결정하고, 로봇은 미리 저장된 자세를 실행한다.

```text
카메라: 빨간 말 2번 → 7번
AI: 노란 말 4번 → 1번
로봇: cell_4_grasp → cell_1_grasp
```

셀 번호는 다음과 같이 고정한다.

```text
1 | 2 | 3
--+---+--
4 | 5 | 6
--+---+--
7 | 8 | 9
```

### 필수 티칭 포인트

- `home`
- `transit`
- `cell_1_hover` ~ `cell_9_hover`
- `cell_1_grasp` ~ `cell_9_grasp`
- `stock_1_hover` ~ `stock_3_hover`
- `stock_1_grasp` ~ `stock_3_grasp`

`hover`는 다른 말을 건드리지 않는 안전 높이, `grasp`는 집거나 놓는 실제 높이다. 관절각 기반 제어에서는 두 자세를 따로 저장한다.

### 표준 이동

```text
출발 hover
→ 출발 grasp
→ 집게 닫기
→ 출발 hover
→ transit
→ 도착 hover
→ 도착 grasp
→ 집게 열기
→ 도착 hover
→ transit
→ home_high
→ home
```

수평 이동은 항상 안전 높이에서 수행한다. 통신 오류나 동작 실패 시 다음 단계로 넘어가지 않는다.

### 사람 턴 완료 입력

개발 및 첫 실기에서는 키보드 `Enter`를 사람 턴 완료 신호로 사용한다. 참가자는 말을 놓거나 옮긴 뒤 작업 영역에서 손을 완전히 빼고 `Enter`를 누른다. 프로그램은 이 입력 뒤에만 안정화된 카메라 프레임을 읽고, 유효한 사람 수로 판정된 경우에만 로봇을 움직인다.

현장에서는 브라우저의 `내 차례 완료`와 키보드 `Enter`만 사용한다. 입력은 사람
차례에만 활성화하고 로봇 동작 중에는 무시한다. 완료 입력은 턴 제출용이며 운영자용
중단 및 물리 전원 차단 절차와 구분한다.

## 6. 카메라 캘리브레이션

### ArUco 정책

MVP에서는 ArUco 마커를 사용하지 않는다.

- 카메라와 보드는 설치 후 고정한다.
- 체스판 외곽과 격자 무늬가 명확하다.
- 말이 셀보다 작아 무늬가 충분히 보인다.
- 현장 설치 때 재캘리브레이션 도구를 사용한다.

실제 테스트에서 카메라 흔들림이나 보드 자동 검출 실패가 반복될 때만 방향 마커 또는 ArUco 추가를 검토한다.

### 보드 검출 이중화

기본 방식은 체스판 자동 검출이다.

- 흑백 외곽 사각형 검출
- 격자선과 교차점 검증
- 원근 변환 행렬 계산
- 정면 보드 영상 생성
- 3×3 셀 ROI 생성

3×3 체스판은 대칭이므로 캘리브레이션에 0°, 90°, 180°, 270° 회전을 저장하고
운영자 화면에는 외부 규칙과 같은 1~9번 오버레이를 제공한다.

자동 검출 실패 시 운영자가 다음 순서로 네 모서리를 클릭한다.

```text
좌상단 → 우상단 → 우하단 → 좌하단
```

수동 방식은 반드시 제공하며 자동 검출 성공을 설치의 필수 조건으로 두지 않는다.

### 렌즈 보정

보드 중앙을 바라보고 왜곡이 작으면 네 모서리 원근 변환만 사용한다. 외곽 직선이 심하게 휘거나 모서리 셀 분할이 어긋나면 별도의 인쇄용 캘리브레이션 체스보드로 카메라 내부 파라미터를 구한다. 게임 보드에 영구 마커를 추가할 필요는 없다.

### 색상 보정

1. 현장 조명에서 빨간 말을 중앙 셀에 놓고 `빨강 등록`을 누른다.
2. 중앙 ROI의 HSV 분포를 측정한다.
3. 노란 말도 같은 방식으로 등록한다.
4. 생성된 마스크와 셀 판정을 화면으로 확인한다.

빨강은 Hue 양 끝 범위를 모두 지원하고, 흑백 보드는 낮은 채도 기준으로 제외한다. 셀 전체보다 중앙의 축소 ROI를 우선 검사한다.

### 카메라 캘리브레이션 도구

예정 명령:

```bash
python -m raccoonbot_game.tools.calibrate_camera
```

필수 기능:

- 카메라 및 해상도 선택
- 실시간 프리뷰
- 자동 보드 검출
- 네 모서리 수동 지정
- 원근 변환 결과와 셀 번호 표시
- 보드 방향 회전
- 빨강 및 노랑 샘플 등록
- HSV 마스크 표시
- 셀별 판정과 신뢰도 표시
- 카메라 제어값 표시
- 프로필 저장 및 불러오기
- 9칸 검증 모드

집과 현장 프로필을 구분한다.

```text
data/calibration/home.json
data/calibration/venue.json
```

저장 항목:

- 카메라 장치, 해상도 및 제어값
- 보드 네 모서리와 방향
- 원근 변환 정보
- 빨강과 노랑 HSV 범위
- 셀 점유 판정 임계값
- 프레임 안정화 기준

운영자가 현장에서 3분 이내에 카메라 캘리브레이션을 완료하는 것을 목표로 한다.

## 7. 로봇 캘리브레이션

예정 명령:

```bash
python -m raccoonbot_game.tools.calibrate_robot
```

필수 기능:

- 연결 상태 확인
- 홈 이동
- 조인트 또는 Cartesian 조그
- 그리퍼 열기와 닫기
- 현재 자세 표시
- 자세 이름별 저장
- 저장 자세 시험 이동
- 전체 셀 순회 테스트
- 비상 정지
- 프로필 저장과 불러오기

예정 파일:

```text
data/calibration/robot.json
```

로봇과 보드를 같은 베이스판으로 운반하면 현장에서 0번, 4번, 8번만 빠르게 점검한다. 둘 중 하나를 분리했거나 충격을 받았다면 전체 9칸과 거치대를 다시 확인한다.

### 모듈 책임

- `game.py`: 규칙, 차례, 단계, 승패와 반복 판정
- `ai.py`: 합법 수 평가, 난이도와 무작위성
- `vision/`: 보드 정렬, 색상 인식, 상태 안정화, 사람 행동 검증
- `robot/`: 실제 장비와 시뮬레이터 인터페이스, 티칭과 안전 이동
- `app/`: 전체 상태 머신, 게임 통합과 UI
- `tools/`: 하드웨어 진단과 현장 캘리브레이션

실제 장비가 없어도 개발할 수 있도록 `SimulatedRobot`과 `RaccoonBotController`가 같은 인터페이스를 구현한다.

## 9. 애플리케이션 상태 머신

```text
STARTUP
→ HARDWARE_CHECK
→ CALIBRATION_CHECK
→ IDLE
→ HUMAN_TURN
→ HUMAN_MOVE_VALIDATION
→ ROBOT_THINKING
→ ROBOT_MOVING
→ ROBOT_MOVE_VERIFICATION
→ HUMAN_TURN
→ FINISHED
```

복구 불가능한 오류 발생 시:

```text
ANY STATE → ERROR → ROBOT STOP → OPERATOR ACTION
```

### 참가자 턴

1. 로봇이 정지한다.
2. 참가자가 말 하나를 배치하거나 이동한다.
3. 참가자가 외부 완료 버튼을 누른다.
4. 카메라 영상이 안정되고 손이 빠진 상태를 확인한다.
5. 이전 상태와 새 상태를 비교한다.
6. 합법 수면 게임에 반영하고, 불법 수면 원상 복구를 안내한다.

### 로봇 턴

1. AI가 수를 선택한다.
2. 현재 카메라 상태와 내부 게임 상태가 같은지 확인한다.
3. 로봇이 말을 집어 옮긴다.
4. 로봇이 안전 위치로 이동한다.
5. 카메라가 예상 결과를 검증한다.
6. 불일치하면 추가 로봇 동작 없이 오류 상태로 전환한다.

## 10. 비전 및 행동 검증

### 처리 과정

```text
카메라 프레임
→ 보드 원근 변환
→ 9개 셀 ROI
→ HSV 변환
→ 빨강·노랑 마스크
→ 셀별 색상 비율
→ EMPTY / HUMAN / ROBOT
→ 여러 프레임 안정화
```

최근 5~10프레임 중 동일한 상태가 안정적으로 유지될 때만 결과를 확정한다. 손, 그림자 또는 움직임이 감지되면 판정을 보류한다.

배치 단계 정상 변화:

- 빈칸 한 곳만 참가자 말로 바뀐다.
- 기존 말은 변하지 않는다.

이동 단계 정상 변화:

- 참가자 말 한 곳이 빈칸으로 바뀐다.
- 빈칸 한 곳이 참가자 말로 바뀐다.
- 로봇 말은 변하지 않는다.

말 두 개 이동, 상대 말 이동, 보드 밖 제거, 점유 칸 겹침은 불법 수로 처리하고 로봇 명령을 생성하지 않는다.

## 11. UI 및 운영 기능

참가자 화면:

- 현재 보드와 차례
- `말 하나를 놓아주세요`
- `자기 말 하나를 빈칸으로 옮겨주세요`
- `손을 빼고 완료 버튼을 눌러주세요`
- `라쿤봇이 생각 중입니다`
- `라쿤봇이 움직이고 있습니다`
- 도전자 승리, 라쿤봇 승리, 라쿤봇 방어 성공

운영자 기능:

- 게임 초기화
- 카메라와 로봇 재연결
- 로봇 홈 복귀
- 카메라 재캘리브레이션
- 로봇 위치 점검
- 강제 재인식
- 비상 정지

## 12. 안전 원칙

- 참가자 턴과 로봇 턴을 상태 머신으로 분리한다.
- 완료 버튼을 누르기 전에는 로봇이 움직이지 않는다.
- 손 감지는 보조 수단으로만 사용한다.
- 운영자가 즉시 사용할 수 있는 물리 정지 수단을 둔다.
- 수평 이동은 안전 높이에서 수행한다.
- 카메라 또는 통신 연결이 끊기면 추가 동작을 하지 않는다.
- 로봇 동작 중 참가자 입력은 무시한다.
- 말은 가볍고 모서리가 둥근 재질로 만든다.
- 작업 영역을 표시하거나 투명 가드를 설치한다.

## 13. 단계별 개발 계획

### 단계 0: 게임 엔진 보완

현재 기본 게임 엔진과 AI가 구현되어 있다.

추가 작업:

- AI 방어 확률을 명시적인 정책으로 분리
- 게임 상태 직렬화
- 전체 승리선, 반복, 턴 제한과 난수 재현 테스트

완료 조건:

- 모든 규칙 단위 테스트 통과
- 고정 난수 시드에서 AI 행동 재현 가능

### 단계 1: 하드웨어 연결 검증

작업:

- Jetson OS, JetPack 및 Python 버전 기록
- RGB 카메라 프레임 획득
- Mini Dongle+ USB 인식
- 라쿤봇 연결, 홈, 관절 이동, 그리퍼, 정지 검증

완료 조건:

- Jetson에서 카메라 프레임을 지속적으로 읽음
- Jetson에서 라쿤봇 단일 동작을 실행함
- 그리퍼를 반복 제어함
- 통신 실패 시 안전하게 정지함

Python 직접 제어가 불가능하면 Chromium Web Serial 제어 페이지와 Python 간 로컬 WebSocket 브리지를 사용한다.

### 단계 2: 물리 시제품

작업:

- 임시 체스판, 말과 거치대 제작
- 보드와 카메라 고정
- 전체 작업점 도달 가능성 확인

완료 조건:

- 9칸과 거치대 모두 도달 가능
- 그리퍼가 말을 안정적으로 잡음
- 카메라에서 보드가 잘리지 않고 무늬가 충분히 보임

### 단계 3: 로봇 제어와 티칭

작업:

- 공통 로봇 인터페이스와 시뮬레이터
- 실제 RaccoonBot 어댑터
- 로봇 캘리브레이션 도구
- `move_stock_to_cell()`과 `move_piece()`

완료 조건:

- 키보드로 거치대에서 원하는 셀로 이동
- 키보드로 임의 셀에서 빈셀로 이동
- 전체 셀 조합에서 충돌 없음
- 최소 30회 연속 픽앤플레이스 성공

### 단계 4: 카메라 캘리브레이션 도구

작업:

- 자동 체스판 검출
- 네 모서리 수동 지정
- 방향과 셀 번호 확인
- 빨강과 노랑 등록
- 프로필 저장과 9칸 검증

완료 조건:

- 집과 현장 프로필 별도 생성
- 자동 검출 실패 시 수동 방식으로 진행
- 재실행 후 동일한 보드 분할
- 3분 이내 현장 캘리브레이션

### 단계 5: 보드 인식과 행동 검증

작업:

- 셀별 상태 판정
- 프레임 안정화
- 움직임 중 판정 보류
- 이전·새 상태 비교와 불법 수 안내

완료 조건:

- 통제된 현장 조명에서 100회 상태 판정 시험
- 정상 행동을 정확한 게임 액션으로 변환
- 불법 행동에서 로봇 명령 없음

### 단계 6: 전체 통합과 UI

작업:

- 상태 머신
- 게임, AI, 비전과 로봇 연결
- 로봇 동작 결과 재검증
- 참가자 화면과 운영자 기능

완료 조건:

- 운영자 개입 없이 한 게임 완료
- 정상 게임 10회 연속 완료
- 오류에서 안전 상태 전환
- 초기화 후 새 게임 정상 시작

### 단계 7: 현장 운영 리허설

작업:

- 현장 조명에서 재캘리브레이션
- 카메라 및 동글 분리 후 오류 표시 확인
- 잘못된 말 이동과 집기 실패 시험
- 설치, 초기화와 복구 매뉴얼

완료 조건:

- 오류 시 로봇 추가 동작 없음
- 운영자 30초 이내 일반 오류 복구
- 사용자 단독 UI 게임과 복구 리허설 완료

## 14. 테스트 항목

### 게임 및 AI

- 8개 승리선
- 배치와 이동의 합법·불법 수
- 상대 말 및 동일 위치 이동 금지
- 반복과 이동 수 제한
- AI 즉시 승리와 난이도 확률

### 비전

- 빈 보드와 모든 말 개수 조합
- 빨강과 노랑의 모든 9칸 위치
- 말이 중앙에서 약간 벗어난 경우
- 밝기 변화, 그림자, 손, 프레임 흔들림
- 카메라 재연결

### 로봇

- 거치대 3개 집기
- 9개 셀 집기와 놓기
- 가장 긴 셀 이동
- 그리퍼 실패, 정지, 홈, 통신 끊김

### 통합

- 배치 단계 승리와 이동 단계 승리
- 반복 및 턴 제한
- 사람의 불법 이동
- 완료 버튼 조기 입력
- 로봇 집기 실패
- 예상 상태와 실제 상태 불일치
- 게임 종료 후 초기화

## 15. 오류 처리

| 오류 | 시스템 동작 | 운영자 조치 |
|---|---|---|
| 카메라 프레임 없음 | 진행 중지 | 연결 확인 후 재연결 |
| 보드 검출 실패 | 로봇 정지 유지 | 프로필 확인 또는 재캘리브레이션 |
| 색상 판정 불확실 | 입력 보류 | 손과 그림자 제거 후 재인식 |
| 참가자 불법 수 | 로봇 명령 금지 | 화면 안내대로 원상 복구 |
| 동글 연결 끊김 | 오류 상태 | 동글과 로봇 재연결 |
| 로봇 이동 실패 | 추가 이동 중지 | 안전 확인 후 수동 복구 |
| 결과 검증 불일치 | 내부 상태 갱신 금지 | 실제 보드 확인 후 재인식 |

카메라 재판정처럼 안전한 작업만 자동 재시도한다. 로봇 물리 동작은 운영자 확인 없이 반복하지 않는다.

## 17. 현장 설치 절차

1. 베이스판을 안정적인 테이블에 설치한다.
2. 로봇, 보드, 거치대와 카메라 고정을 확인한다.
3. Jetson, 카메라, Mini Dongle+와 전원을 연결한다.
4. 하드웨어 진단 도구를 실행한다.
5. 카메라 캘리브레이션 도구를 실행한다.
6. 체스판 검출과 1~9번 방향을 확인한다.
7. 필요하면 네 모서리를 수동 지정한다.
8. 현장 조명에서 빨강과 노랑을 등록한다.
9. 9칸 인식 검증을 실행한다.
10. 로봇의 0번, 4번, 8번과 거치대를 점검한다.
11. 테스트 게임을 최소 3회 진행한다.
12. 비상 정지와 초기화 절차를 확인한다.

목표 시간:

- 카메라 캘리브레이션 3분 이내
- 로봇 빠른 점검 5분 이내
- 테스트 게임을 포함한 전체 준비 15분 이내

## 20. 최종 리허설 작업

1. 행사 노트북과 Jetson을 USB-C로 직결하고 SSH 터널 UI를 연다.
2. 현장 캘리브레이션 탭에서 보드 방향과 빨강·노랑 인식을 확인한다.
3. 쉬움 AI로 빈 판 한 게임을 완주한다.
4. 인식 재시도, 게임 중단, 화면 초기화와 새 게임 복구 흐름을 확인한다.
5. 즉시 정지가 필요한 상황의 물리 전원 차단과 사람 접근 통제를 리허설한다.
